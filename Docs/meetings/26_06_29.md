      - **Formula**: Adaptive time interval heuristic = 0.5 x median_free_flow_tt_route.
      - **Intuition**: The median travel span 2 time intervals.
      - If the median_free_flow_tt_route is small, the time interval will be small.

         In Sioux_Falls the median is 56 sec. -> time interval = 28 seg

To gain insights into the metric behavior I create the script "/home/miguel/6.Projects/Thesis/src/tools/plot_congestion_metric.py", to visualize the metric values for different demand levels. I see that my congestion metric seems to not be appropiate since it does not differentiate between low congestion and moderate congestion. But first it tells me that before changing metric I should use the same OD matrix than the one used during training. Basically the process is that before the demand calibration generated a random OD matrix, and then it computed congestion on that matrix, and then it passed the number of agents to scenario. Now the demand calibration uses the same OD matrix than used during training, and passes the OD matrix of the last iteration to scenario.

I calibrate using shortest paths. If everyone behaves selfishly by taking the shortest path, the network has this congestion.
With this new approach, less agents are needed to achieve the same congestion ratio, because before demand calibration spread all the agents over the network, whereas now are spread only over a few ods, so many agents computing for same routes, then is gonna be more congested.
I also noticed that with this new approach, I may get a nº of agents that produces a big congestion during simulation in demand calibration (simulation takes much longer, teleports...) whereas in training with the same number of agents even on the first episodes works fine. That is because demand calibration agents for same OD only take shortest path, while in training they can take among 5 alternative routes.
The consequence is that calibration slightly overestiamtes congestion for a given demand (shortest path vs 5 alternative routes), but approximation is OK.

The new congestion metric to use that has yet to be implemented is the mean of the ratios trip travel time / free flow travel time for each agent.
